# Completion procedure reads past work

## Goal

`core/shared/complete-procedure.md` names the milestones tool's `tasks <path> --with-body` query, its full fixed command shown, as the discretionary read of why a file is the way it is before editing it, with `show <milestone path>` as the follow-up for a decision's own words. The read is triggered by a file the task edits rather than creates whose shape the milestone's `requirements.md` does not explain, and is taken at step 2 for the files the task names up front, where what it surfaces may fix a criterion, and at step 3 for the edits only, the acceptance bar never re-deriving on it. The milestones tool stays unchanged and no test is added for the read; the docs, the `CLAUDE.md` invariants, and the rebuilt host trees follow, and `ideas/milestones_addressed_by_path.md` records step 5 as done, the choice of `tasks` over `record` included, and carries the written plan for the field measurement that decides whether the read stays discretionary: what is counted, over which runs, and the result that makes the read required.
