# Milestone 47: Antigravity global install and agent tools

## Goal

Fix the two Antigravity runtime failures reported in `temp/agy_runtime_issues_report.md`: grant write and shell tool access to the `provide-alternatives-to-open-question` and `complete-task` subagents in the Antigravity host tree through a `tools:` list in each agent's frontmatter naming the host's file-writing and command-running tools, the one grant the installed `agy` honours for a Markdown-defined agent (the `enable_write_tools` key is read only by the host's `define_subagent` tool, which itself materializes its grant as a `tools:` list, and is ignored in an agent file's frontmatter), and standardize Antigravity on the global `~/.gemini/config/plugins/cairn` installation path across `plugin_root`, the rendered host tree, and the installation documentation. Add a repeatable, on-demand test suite that drives the real `agy` CLI to verify global plugin-root resolution and subagent write/shell tool execution, kept out of the default `pytest` and CI runs so it executes only when requested or when the Antigravity host integration changes.

The definition's templates are `README.md`, `CONTRIBUTING.md`, `plugin.json`, and `.github/workflows/traffic-badges.yml`; the README template's `### Antigravity` section is a `mkdir -p .agents/plugins/cairn` followed by a `curl | tar` extract into it, and the root `README.md` carries that section word for word. ## Decisions

### Antigravity host tree

- **Plugin root is the tilde literal.** `plugin_root` in `scripts/hosts/antigravity/settings.toml` becomes `~/.gemini/config/plugins/cairn`, the form the host's own plugin guide writes the path, so every rendered read path and `python3` command in the Antigravity tree names that tilde path. The literal is fixed at build time; `core/`, the dispatch prompts, and the agent files are unchanged, and the runner gets no resolution rule. Whether the host's file-reading tool takes a tilde path is left to the suite's resolution test to pin.
- **The write-tools key reaches the agents through a frontmatter slot.** A named slot placeholder sits inside the frontmatter of both `core/agents/*.md` files; the Antigravity definition's value file holds `enable_write_tools: true`, and the Claude Code and Codex definitions declare the slot with an empty value file, placed so an empty value leaves no blank frontmatter line. No build code, schema, or `strip_frontmatter_keys` list changes, `color` stays the one structural exception, and the rendered frontmatter is validated by the existing YAML checks.
- **The build gains a declared required-keys check.** Every host definition declares one new settings key, kept in the shared key set, naming the frontmatter keys and values each rendered agent file must carry: `enable_write_tools = true` for Antigravity, empty for Claude Code and Codex. `check_host_tree` gains one generic check that fails `--check`, and so the drift gate and CI, when a rendered agent lacks a declared key or carries a different value. The check is host-neutral data plus generic Python, mirroring `stripped-key-present`; the agy suite stays the behavioural check beside it.

### Installation documentation

- **The install docs carry a removal instruction for stale workspace-local copies.** The README's Antigravity installation section, in the template under `scripts/hosts/antigravity/` and the root `README.md` that carries it word for word, gains a short note for projects that extracted cairn under an earlier release: remove the project's `.agents/plugins/cairn/` directory, with the literal command and one clause on why (the old copy is discovered beside the global one and predates the subagents' write and shell tools). The note says nothing about how the host ranks or merges the two copies.
- **The install section carries a first-install restart note.** Both the README template and the root `README.md` follow the extract command with one sentence: Antigravity discovers a new plugin directory only on startup, so a running agy session must be restarted after the extract. The sentence is identical in both copies, covers the first install only, says nothing about re-extracting a newer release over an existing global copy, and adds no listing or verification command.
- **Every tracked stale path mention is corrected.** Beyond the two installation sections and the host definition's comments, the milestone corrects every tracked, non-historical statement that names the workspace-local plugin path or says the plugin loads from the working directory: the `--add-dir` bullet in `docs/ways-of-using-cairn.md`, the Antigravity manifest location in `.github/ISSUE_TEMPLATE/bug.yml` (to `~/.gemini/config/plugins/cairn/plugin.json`), and the opening sentence of the `scripts/hosts/antigravity/README.md` template describing extraction into a workspace's `.agents/plugins/cairn/`. `CHANGELOG.md` entries and finished milestones' files stay as written.

### The agy suite

- **The suite is a separate pytest directory outside `testpaths`.** It lives in its own directory at the repository root (for example `agy_tests/`) with its own `conftest.py` holding its fixtures (seeded repositories, an agy launcher). `testpaths = ["tests"]` and the CI workflow stay as they are, so `uv run pytest` and the 3.9 floor run never reach it, and no marker, `addopts`, naming convention, or environment variable is involved. It is invoked by naming the directory: `uv run pytest agy_tests`.
- **The subagent probe dispatches both agents directly with their real inputs.** The suite's headless `agy -p` prompts dispatch each plugin agent directly, bypassing the orchestrator skills: `provide-alternatives-to-open-question` with a fixture Short Title, the fixture milestone directory, and a scratch directory the suite created, and `complete-task` with the heading of one trivial fixture task. The pass signal is the files each agent lands: the alternatives scratch file holding `<alternative>` elements, and the fixture task's section moved from `TASKS_TODO.md` into `TASKS_DONE.md` by the task-list tool with the two paths staged. No trivial write-and-run task replaces an agent's real contract, and no final message or transcript record is read.
- **The suite runs at the host's default model and effort with agy's own print timeout.** Every `agy -p` line the suite runs carries no `--model` and no `--effort`, running at the account's defaults as the documented chains in `docs/ways-of-using-cairn.md` do, and carries one fixed `--print-timeout` value chosen by the suite, so agy itself ends any headless run that exceeds the bound. The suite enforces no wall-clock limit of its own and holds no model id.
- **The suite drives the installed global copy after checking it against the build.** The suite drives the copy already at `~/.gemini/config/plugins/cairn` in the user's real `HOME` and installs nothing, but before any agy process starts it compares that copy byte for byte with the repository's `hosts/antigravity/` tree and stops on any difference, naming the remedy (re-extract or copy the built tree). It never writes to the user's installation; replacing the copy stays an explicit act of the user's own.
- **The resolution test covers the orchestrator's read and command.** The suite's plugin-root resolution test is one dispatch-free headless agy process whose printed output asserts separately that the orchestrator read a shared procedure at the global path and ran a `python3` tool command there. No dispatched agent's resolution is asserted by this test; the agent context's reads and commands are exercised by the subagent probe's real-input dispatches, whose landed files cannot appear without them.
- **Each agy process runs in a committed fixture copied to a temporary directory.** A new committed directory under `tests/fixtures/` holds a small project tree: `milestones/README.md` with its pointer, one milestone directory with `requirements.md`, an `open_questions.xml` holding a few bare blocks, and the two task files, the latter carrying the one trivial task the direct dispatches need. For each agy process the suite copies it to a fresh temporary directory, as `conftest.py`'s `milestone_dir` fixture does for the tool tests, then runs `git init` and an initial commit there. The setup depends on no plugin tool being correct; a fixture gone stale is caught by the tools refusing it at run time.
- **A missing prerequisite stops the suite before any test with one line.** Before any test runs, the suite checks its prerequisites in one up-front check: agy resolvable on `PATH`, the global plugin copy present at `~/.gemini/config/plugins/cairn`, and that copy matching the built tree. When any is missing, it stops the whole run with a non-zero exit and one line naming the missing prerequisite, reporting no per-test outcome and never skipping; every prerequisite is treated the same way.
- **The integration-change trigger is a contributor sentence plus a gated release check.** Both mechanisms work over one shared narrow path set: `scripts/hosts/antigravity/`, `core/agents/*.md`, `scripts/build_hosts.py`, and the suite itself. A sentence in `CONTRIBUTING.md`'s `## Development` section requires an agy suite run before committing a change to those paths. A new pre-flight check in the release-plugin skill runs the suite when any of those paths changed since the last release tag and stops the release on a failure; releases with no such change pay nothing, and the check stays within the pre-flight's no-write rule because the suite writes nothing to the installation.
- **The hands-on check block is updated and carries no suite pointer.** This milestone's hands-on run rewrites the dated block in the header of `scripts/hosts/antigravity/settings.toml` as a new check against agy 1.4.0, naming the global `~/.gemini/config/plugins/cairn` path as the install checked, the `enable_write_tools` check on both agents, and the points the 2026-10-13 run sourced (dispatch, waiting, continuing an agent, context file), each re-checked or carried forward. It stays the one record of what was checked, carries no reference to the agy suite, and the `CLAUDE.md` invariant stays as worded.
