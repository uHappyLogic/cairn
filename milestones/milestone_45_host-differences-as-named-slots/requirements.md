# Milestone 45: Host differences as named slots

## Goal

Make named slots the one way host differences reach `core/`. The build gains file-backed slot values beside the inline TOML ones, plus a lightweight pytest of its rendering, which runs under the pinned interpreter. Every host-conditional passage left in `core/` becomes a slot, so each host's tree describes only its own mechanism: the alternatives pass's repair branches, its wait and batch wording, and the "where the host can" phrasing. Every Antigravity slot value is rewritten from a hands-on check against a locally installed `agy`, covering dispatch, waiting, continuing an agent, and the context file. The `CLAUDE.md` invariants and `docs/` are rewritten to match: slots are preferred over capability-conditional prose, a rendered tree must never name another host's mechanism (a development rule, not a check), and the Claude/Antigravity byte-identity is retired as a test.

## Relevant starting state

### Host build and slot rendering

`scripts/build_hosts.py` (739 lines; imports `tomllib` and PyYAML, so it needs Python 3.11+) is the one generic build. It discovers every `scripts/hosts/<host>/settings.toml`, validates it against a fixed key schema (`plugin_name`, `plugin_root`, `plugin_dir`, `prose_drop_patterns`, `strip_frontmatter_keys`, `renames`, `exclude`, `[layout]`, `[slots]`), renders `core/` into a temporary directory, runs its check set, and only then swaps the result into `hosts/<host>/`. Slot values are read straight from the TOML `[slots]` table and must be strings (the loader refuses `slots.<NAME> must be a string`); there is no file-backed form, no include, and no per-slot file lookup anywhere in the script. A slot name must match `[A-Z][A-Z0-9_]*`, may not be `PLUGIN_ROOT`, `VERSION`, or `NAME`, and its value may carry `{{PLUGIN_ROOT}}` but no other `{{`. Per `core/` text file the render order is `fill_slots` (one regex pass that leaves an undeclared placeholder in place), then the `{{PLUGIN_ROOT}}` replacement, then `prose_drop_patterns`, then frontmatter-key stripping; the template files beside `settings.toml` get only `{{VERSION}}` and `{{NAME}}`. The checks that bear here are `slot-declaration` (every declared slot appears in `core/`, and every definition declares the same name set), `unfilled-placeholder` (any `{{` not preceded by `$` in a rendered tree), and `host-name-in-core` (no definition directory name standing as its own word in any `core/` file). `--check` renders the same way and compares byte-for-byte against the committed trees; the script never invokes git.

### The eight declared slots

All three definitions declare the same eight slots: `CONTEXT_FILE`, `COMPLETE_TASK_DISPATCH`, `COMPLETE_TASK_PROMPT_INSTRUCTIONS`, `ALTERNATIVES_DISPATCH`, `ALTERNATIVES_PROMPT_INSTRUCTIONS`, `ALTERNATIVES_AGENT`, `AGENT_TOOL`, and `ALTERNATIVES_CONCURRENCY`. `CONTEXT_FILE` is used at about thirty sites across eleven skills and `core/shared/complete-procedure.md`; the other seven appear in exactly two skills: `complete-all-tasks` (the dispatch sentence and the prompt opener) and `provide-alternatives-to-all-open-questions` (`ALTERNATIVES_CONCURRENCY` as the whole paragraph opening step 3, `ALTERNATIVES_DISPATCH` and `ALTERNATIVES_PROMPT_INSTRUCTIONS` in sub-step b, and `AGENT_TOOL` twice with `ALTERNATIVES_AGENT` once inside the sub-step e repair branches). No agent file and no other shared procedure carries a placeholder other than `{{PLUGIN_ROOT}}`. Each `settings.toml` holds its values inline (104 lines for Claude Code and for Antigravity, 119 for Codex), the multi-line ones as TOML `'''` literal strings, each preceded by a comment naming what the slot stands for and why this host's value is what it is; `ALTERNATIVES_CONCURRENCY` runs thirteen lines in the Claude Code and Antigravity files and twenty in the Codex one.

### Test suite and interpreters

`tests/` holds `conftest.py` and eighteen flat `test_<name>.py` files, all for the two tools under `core/tools/`, which they drive as subprocesses under `sys.executable` from the golden fixture directories `tests/fixtures/{bare,annotated,empty,entities}/`; `pyproject.toml` sets `pythonpath = ["core/tools"]` and `testpaths = ["tests"]`, and `conftest.py` sets `sys.dont_write_bytecode` so no `__pycache__` lands under `core/`. The pinned run (`uv run pytest`) uses the `.python-version` interpreter (3.13) with the project's PyYAML and the locked pytest 8.4+; the floor run (`uv run --no-project --python 3.9 --with pytest pytest`) has neither PyYAML nor `tomllib` and collects the same `testpaths`, so a test placed under `tests/` runs under both interpreters as the suite stands. `.github/workflows/drift-gate.yml` runs `--check`, the pinned pytest, and the floor pytest as three steps of one job on push and pull request.

### Known gaps

The build has no file-backed slot values. No pytest exercises the build's rendering. `core/` still carries the four capability-conditional passages named above, and the Antigravity slot values have never been written from a check of Antigravity itself.

## Decisions

### Slot value storage

Every slot value of every host definition is held in a file, the one-word and empty values included (`CONTEXT_FILE`, and the empty `COMPLETE_TASK_PROMPT_INSTRUCTIONS` and `ALTERNATIVES_PROMPT_INSTRUCTIONS` of Claude Code among them), so no `settings.toml` keeps an inline `[slots]` value. The rule is a documented convention only: the build keeps accepting the inline form beside the file-backed one, and nothing refuses an inline value.

A file-backed value is bound inside the existing `[slots]` table: the slot's entry is written as an inline table, `NAME = { file = "slots/NAME.md" }`, beside the plain string entries, with the path relative to the definition directory and kept under its `slots/` subdirectory, which template discovery skips. The loader accepts either a string or a one-key `{ file }` table for each slot, and refuses a missing file or a path outside `slots/`. Every slot stays declared once in the one table with its comment above its entry.

### Build rendering test

The rendering test is one full render of a small synthetic `core/` and one synthetic host definition (a `settings.toml` with inline and file-backed slots, plus whatever templates it needs) into a `tmp_path` directory, with the rendered files asserted, including a file-backed value landing in rendered output in the right substitution order. It reaches the build by importing it in-process and monkeypatching its module-level path constants (`CORE_DIR`, `LICENSE_FILE`, and `DEFINITIONS_DIR` where discovery is used) onto the fixture, then calling `load_definition` and `render_host`. The build code is unchanged for the test's sake; the test does not exercise `main`'s orchestration or the check set.

### Slots for the alternatives pass's host-conditional passages

Two new slots replace the four capability-conditional passages of `provide-alternatives-to-all-open-questions`. The opening paragraph's concurrency phrase gets its own slot. One repair slot holds the sub-step e lead-in, the repair branches as each host actually has them, and the repair-wait sentence; sub-step e is reordered in `core/` so that slotted text is contiguous ahead of the fixed corrective message, its fill rule, and the one-repair cap, which stay in `core/`. `ALTERNATIVES_CONCURRENCY` stays as it is. The `AGENT_TOOL` and `ALTERNATIVES_AGENT` slots are retired, their wording written literally inside each host's repair value, so the rule that a slot value carries no placeholder other than `{{PLUGIN_ROOT}}` stands.

### Per-host slot value sourcing

The Claude Code values of the new slots are lifted from the arm of today's capability-conditional wording that applies to Claude Code, kept as written except where a check contradicts it. The evidence is a hands-on check against the locally installed `claude` covering the same four points the goal names for Antigravity (dispatch, waiting, continuing a finished agent, the context file), with the documentation consulted alongside.

The Codex values for the repair branches and the repair wait are rewritten from Codex's documentation plus a hands-on run of the locally installed `codex` that exercises exactly what those values describe: sending a follow-up to a finished subagent, re-spawning a fresh generic subagent, and waiting with `wait_agent` on a repair set alone. The eight existing Codex values are not re-checked and stay as they are unless the run contradicts one the new values depend on.

### Antigravity context file

The Antigravity `CONTEXT_FILE` value becomes `AGENTS.md` at the workspace root, so the Antigravity and Codex trees name the same file. The Antigravity README template's `/init` sentence is rewritten to name it too. The value stays a plain root-level file name, so no `core/` sentence about the workspace root or the bootstrap's file heading changes.

### Antigravity agent loading

Native agent loading on Antigravity is added only when the hands-on check shows that a file the build can already emit is enough: a manifest template beside `plugin.json`, or a relocation through the existing layout and renames. If `agy` needs frontmatter fields the build cannot add today, nothing is added for loading and the Antigravity slot values describe the generic-subagent fallback instead, a subagent told to read the plugin's agent file by its plugin-root path, as the Codex values do. The build's key schema and code gain nothing for agent loading either way.

### Other-host rule

The development rule that a rendered tree never names another host's mechanism covers every file in the tree: the files rendered from `core/` and the host's own templates (README, CONTRIBUTING pointer, manifest, marketplace file, traffic workflow) alike. No file in a tree names another host's mechanism in any form, a contrastive mention of what this host does not use included; a link to the source repository is not a mechanism naming. The Codex README's "never to CLAUDE.md" clause and the Antigravity README's `/init`-into-`CLAUDE.md` instruction are reworded under this rule.

Slot values keep naming no host, their own included: a value reaches its host's mechanism through that host's identifiers (tool names such as `spawn_agent` or `Agent`, config keys such as `agents.max_threads`, file names, command names) and otherwise describes it in host-neutral words such as "this host". The rewritten "name no host" invariant in `CLAUDE.md` states that it covers every rendered runtime file, slot values included. Nothing in the build enforces it in values: `host-name-in-core` keeps scanning `core/` only.

### CONTRIBUTING.md Development section

The section is restructured in this milestone. Its `settings.toml` sentence and check list are replaced by a short description of what a host definition is (settings plus templates, wording differences as named slots whose values sit inline or in files) and a pointer to the build script's docstring as the one complete reference for settings keys and checks; the test paragraph covers the pinned-only build rendering test. The section also states the new development rule for contributors: host differences reach `core/` as named slots rather than capability-conditional prose, and a rendered tree never names another host's mechanism.

### Antigravity command-line facts in docs/ways-of-using-cairn.md

Every Antigravity command-line fact on `docs/ways-of-using-cairn.md` is checked as part of the same hands-on `agy` check and corrected where it differs: the invocation form, `--dangerously-skip-permissions`, `--model` with `agy models`, `--add-dir` and its need on every `agy` line, and the move-a-line rule. The `--effort` value lists are replaced by a pointer to each host's own `--help`, so no effort values are listed on the page for any host.
