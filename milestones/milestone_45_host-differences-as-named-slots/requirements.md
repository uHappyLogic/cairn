# Milestone 45: Host differences as named slots

## Goal

Make named slots the one way host differences reach `core/`. The build gains file-backed slot values beside the inline TOML ones, plus a lightweight pytest of its rendering, which runs under the pinned interpreter. Every host-conditional passage left in `core/` becomes a slot, so each host's tree describes only its own mechanism: the alternatives pass's repair branches, its wait and batch wording, and the "where the host can" phrasing. Every Antigravity slot value is rewritten from a hands-on check against a locally installed `agy`, covering dispatch, waiting, continuing an agent, and the context file. The `CLAUDE.md` invariants and `docs/` are rewritten to match: slots are preferred over capability-conditional prose, a rendered tree must never name another host's mechanism (a development rule, not a check), and the Claude/Antigravity byte-identity is retired as a test.

## Relevant starting state

### Host build and slot rendering

`scripts/build_hosts.py` (739 lines; imports `tomllib` and PyYAML, so it needs Python 3.11+) is the one generic build. It discovers every `scripts/hosts/<host>/settings.toml`, validates it against a fixed key schema (`plugin_name`, `plugin_root`, `plugin_dir`, `prose_drop_patterns`, `strip_frontmatter_keys`, `renames`, `exclude`, `[layout]`, `[slots]`), renders `core/` into a temporary directory, runs its check set, and only then swaps the result into `hosts/<host>/`. Slot values are read straight from the TOML `[slots]` table and must be strings (the loader refuses `slots.<NAME> must be a string`); there is no file-backed form, no include, and no per-slot file lookup anywhere in the script. A slot name must match `[A-Z][A-Z0-9_]*`, may not be `PLUGIN_ROOT`, `VERSION`, or `NAME`, and its value may carry `{{PLUGIN_ROOT}}` but no other `{{`. Per `core/` text file the render order is `fill_slots` (one regex pass that leaves an undeclared placeholder in place), then the `{{PLUGIN_ROOT}}` replacement, then `prose_drop_patterns`, then frontmatter-key stripping; the template files beside `settings.toml` get only `{{VERSION}}` and `{{NAME}}`. The checks that bear here are `slot-declaration` (every declared slot appears in `core/`, and every definition declares the same name set), `unfilled-placeholder` (any `{{` not preceded by `$` in a rendered tree), and `host-name-in-core` (no definition directory name standing as its own word in any `core/` file). `--check` renders the same way and compares byte-for-byte against the committed trees; the script never invokes git.

### The eight declared slots

All three definitions declare the same eight slots: `CONTEXT_FILE`, `COMPLETE_TASK_DISPATCH`, `COMPLETE_TASK_PROMPT_INSTRUCTIONS`, `ALTERNATIVES_DISPATCH`, `ALTERNATIVES_PROMPT_INSTRUCTIONS`, `ALTERNATIVES_AGENT`, `AGENT_TOOL`, and `ALTERNATIVES_CONCURRENCY`. `CONTEXT_FILE` is used at about thirty sites across eleven skills and `core/shared/complete-procedure.md`; the other seven appear in exactly two skills: `complete-all-tasks` (the dispatch sentence and the prompt opener) and `provide-alternatives-to-all-open-questions` (`ALTERNATIVES_CONCURRENCY` as the whole paragraph opening step 3, `ALTERNATIVES_DISPATCH` and `ALTERNATIVES_PROMPT_INSTRUCTIONS` in sub-step b, and `AGENT_TOOL` twice with `ALTERNATIVES_AGENT` once inside the sub-step e repair branches). No agent file and no other shared procedure carries a placeholder other than `{{PLUGIN_ROOT}}`. Each `settings.toml` holds its values inline (104 lines for Claude Code and for Antigravity, 119 for Codex), the multi-line ones as TOML `'''` literal strings, each preceded by a comment naming what the slot stands for and why this host's value is what it is; `ALTERNATIVES_CONCURRENCY` runs thirteen lines in the Claude Code and Antigravity files and twenty in the Codex one.

### The three host definitions

Claude Code: `plugin_root = "${CLAUDE_PLUGIN_ROOT}"`, empty `plugin_dir`, strips no frontmatter key, templates `README.md`, `CONTRIBUTING.md`, and `.github/workflows/traffic-badges.yml`; its slot values name the `Agent` tool with `subagent_type`, the `cairn:` registry names, and `CLAUDE.md`. Antigravity: `plugin_root = ".agents/plugins/cairn"` (a workspace-relative literal, since Antigravity defines no plugin-root variable), empty `plugin_dir`, strips `color`, and adds a `plugin.json` template (`$schema` `https://antigravity.google/schemas/v1/plugin.json`, name, description, version). Every one of its eight slot values is the Claude Code value character for character, including the `Agent` tool, `subagent_type`, the `cairn:` names, and `CONTEXT_FILE = "CLAUDE.md"`, and each value's comment says so ("keeps the wording it has always carried", "carries the Claude Code value verbatim ... so the two trees stay byte-identical"); its README template tells users to run `/init` to document the project in `CLAUDE.md`. Codex: `plugin_root = "${PLUGIN_ROOT}"`, `plugin_dir = "plugins/cairn"`, strips `color`, lays the tree out as a marketplace (`.agents/plugins/marketplace.json` at the root, the plugin under `plugins/cairn/` with its `.codex-plugin/plugin.json`), and differs from the other two on all eight slots: `AGENTS.md`, a `spawn_agent` generic subagent told to read the plugin's agent file by its plugin-root path, and an `ALTERNATIVES_CONCURRENCY` built on `agents.max_threads` rounds, `wait_agent`, and `close_agent`.

### Host-conditional passages still in core/

Beyond the slots, `core/skills/provide-alternatives-to-all-open-questions/SKILL.md` holds four passages that name a capability and leave the choice to the runner, rendered identically into all three trees: the opening paragraph's "they run together where the host allows it"; the sub-step e rule "Repair each question by whichever of these two branches the host supports, in this order", with a "Continue the same agent session" branch ("Where the host can continue a finished agent session and you still hold that dispatch's handle — a follow-up message addressed to the agent id the {{AGENT_TOOL}} returned") and a "Re-dispatch one fresh agent" branch ("Where the host cannot continue a finished agent session, or the handle is gone"); and the repair-wait sentence "Where the single wait is the dispatch call's own blocking form, send every repair without blocking ... otherwise wait on the repair set as the paragraph opening this step describes". The Claude Code and Antigravity `ALTERNATIVES_CONCURRENCY` value is itself capability-conditional ("Where it offers a blocking dispatch form ... Where it offers no blocking form ... Both arms write the same blocks"), so the Antigravity tree today describes two wait mechanisms and two repair mechanisms and names none as its own. A search of `core/` for this kind of wording ("where the host", "blocking form", "wake") finds nothing outside this one skill; the two agent files, the other skills, and the shared procedures carry none.

### The Claude Code and Antigravity trees today

`hosts/claude/` and `hosts/antigravity/` differ under `diff -rq` in every runtime file that references the plugin root, in both agent files, and in the templates (README, CONTRIBUTING, traffic workflow, `plugin.json` against `.claude-plugin/`). After substituting the two plugin-root literals and dropping the agents' `color:` line, every file under `skills/`, `shared/`, `agents/`, and `tools/` is identical between the two trees. That identity is what `CLAUDE.md` calls "the slot operation's end-to-end test (no pytest covers it)"; nothing in the build or in CI checks it.

### Test suite and interpreters

`tests/` holds `conftest.py` and eighteen flat `test_<name>.py` files, all for the two tools under `core/tools/`, which they drive as subprocesses under `sys.executable` from the golden fixture directories `tests/fixtures/{bare,annotated,empty,entities}/`; `pyproject.toml` sets `pythonpath = ["core/tools"]` and `testpaths = ["tests"]`, and `conftest.py` sets `sys.dont_write_bytecode` so no `__pycache__` lands under `core/`. No test imports or runs `scripts/build_hosts.py`; `scripts/` is not on the pytest path and has no `__init__.py`. The pinned run (`uv run pytest`) uses the `.python-version` interpreter (3.13) with the project's PyYAML and the locked pytest 8.4+; the floor run (`uv run --no-project --python 3.9 --with pytest pytest`) has neither PyYAML nor `tomllib` and collects the same `testpaths`, so a test placed under `tests/` runs under both interpreters as the suite stands. `.github/workflows/drift-gate.yml` runs `--check`, the pinned pytest, and the floor pytest as three steps of one job on push and pull request.

### Where the current posture is written down

`CLAUDE.md`'s "Host wording differences are named slots" invariant states that the Claude Code and Antigravity values are identical by design, that this identity is the slot operation's end-to-end test, that `ALTERNATIVES_CONCURRENCY` is the alternatives pass's only host-dependent waiting wording, that the Antigravity value is the Claude Code paragraph "because the repository knows nothing of how Antigravity delivers agent returns or whether it can block on them", and that no slot was added for the batch; the "Runtime files carry no editor-facing prose and name no host" invariant says host-dependent sentences "name the capability, never the host"; the dispatched-agent bullet calls the scratch-directory wording "the same wording in every host tree, so it adds no slot"; `## Development` requires a definition to "declare every wording slot". `docs/design-claims.md` claim 18, "The same behaviour on each host", says "A sentence that depends on a host capability names the capability, and the runtime selects the branch" with the alternatives pass's wait as its example, and claim 13 restates the once-per-run or once-per-wake-up batch. `docs/skill-reference.md`'s alternatives-pass entry calls the wait "the one host-dependent paragraph of the pass" and names Claude Code's `SendMessage` and Codex's rounds inline; `docs/workflow.md` has two sentences of the form "where the host can wait for every subagent in one call (once per round on Codex)". `CONTRIBUTING.md ## Development` describes `settings.toml` as holding "the literal that replaces `{{PLUGIN_ROOT}}`, frontmatter keys to strip, renames, excluded paths, and the layout" and lists the build's checks without naming `[slots]`, `plugin_dir`, `slot-declaration`, or `host-name-in-core`. `milestones/README.md` records slots arriving in milestone 40 (Codex host) and `ALTERNATIVES_CONCURRENCY` taking over return collection in milestone 43.

### Antigravity CLI on this machine

`agy` is installed at `~/.local/bin/agy` and reports version 1.3.1; `agy changelog` lists notes through 1.3.4. Its flags include `-p`/`--print`, `--add-dir`, `--dangerously-skip-permissions`, `--agent <name>` (select a custom agent at launch), `-c`/`--continue` (continue the most recent conversation), `--conversation <id>` (resume by id), `--effort` taking `low|medium|high|xhigh|max`, and `--mode`; its subcommands include `agent`/`agents` (list available agents), `plugin` (`list`, `import`, `install`, `uninstall`, `enable`, `disable`, `validate`, `link`), and `models`. `agy plugin list` shows one import named `cairn`, source `antigravity`, imported 2026-09-04, components `skills` and `agents`; that copy lives at `~/.gemini/config/plugins/cairn` with `agents/`, `shared/`, `skills/`, and a `plugin.json` described as "Ported plugin for cairn" with no version, and it has no `tools/` directory, so it predates the open-question tool. `agy agents` run from this repository prints nothing, and the repository has no `.agents/` directory. The binary's embedded changelog and help text name Markdown custom agents under `{workspace}/.agents/agents/{agent_name}/` with `subagent`, `agents`, `model`, and `tools` frontmatter, an `invoke_subagent` tool and a `define_subagent` mechanism, a root-level `agents.json` for plugins, `~/.gemini/GEMINI.md` and `~/.gemini/AGENTS.md` as global rules files, and `GEMINI.md`, `AGENTS.md`, and `.agents/rules/*.md` as workspace rule paths; `CLAUDE.md` appears in none of those strings. `docs/ways-of-using-cairn.md` gives Antigravity's `--effort` values as `low`, `medium`, or `high`, while the installed `agy --help` lists five.
