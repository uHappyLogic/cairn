## Tool List Locate And Lift Subcommands

Add the tool's read subcommands: `list` printing bare ids in document order with a `--unannotated` filter for blocks carrying no `<recommendation>` element, `locate` taking one or more Short Titles and printing each block verbatim as the file holds it, and `lift` printing the recombined answer text — `<option> — <rationale>` from the block's `<recommendation option="…">` or `<id> — <what-it-is>` from a named `<alternative id="…">` with the `<advantage>`/`<drawback>` children excluded — with ids compared un-escaped and case-folded and a missing block, missing recommendation, or unmatched alternative id failing as one `Error:` line. These are what the rewired skills call in place of the `awk`/`sed`/`grep` idiom, and the work is verified by pytest cases covering each subcommand, its empty-set behaviour, and its error paths.

**Verified:**

- `list MILESTONE_DIR` prints the un-escaped `id` of every `<open-question>` block, one per line in document order (the `annotated` fixture yields `Escape hatch under sole writer`, `Root element form`, `Fixture bare block`; the `entities` fixture yields `Ampersand & angle <brackets>, "quotes", 'apostrophes'`), exit 0; the `empty` fixture prints nothing with exit 0 (`tests/test_list.py`).
- `list --unannotated` (flag before or after `MILESTONE_DIR`) prints in document order only the ids of blocks with no `<recommendation>` element: `Fixture bare block` alone from `annotated`, both ids from `bare`, and nothing with exit 0 from the fully annotated `entities` fixture and from `empty` (`tests/test_list.py`).
- `locate MILESTONE_DIR SHORT_TITLE...` takes one or more Short Titles (`nargs="+"`; none is argparse's exit 2) and prints each named block verbatim — for all six fixture blocks the stdout equals the raw line slice of the golden file from its column-2 `<open-question id="…">` line through its `</open-question>` line, entities and indentation intact — consecutively in the order named and once per block even when a title is repeated; an unknown title, alone or among known ones, fails with empty stdout as `Error: no <open-question> block has the id "…"; the document holds "…", "…"` (or `the document holds no blocks` on the `empty` fixture) (`tests/test_locate.py`).
- `lift MILESTONE_DIR SHORT_TITLE` prints exactly one line `<option> — <rationale>` (spaced em dash) from the block's `<recommendation option="…">`; `lift … --alternative ALTERNATIVE_ID` prints `<id> — <what-it-is>` using the stored alternative id and only its what-it-is text, with the `<advantage>`/`<drawback>` children excluded; both values are printed un-escaped (`A & B — One rule for text & attributes: <, >, ", '.` from the `entities` fixture), and an empty rationale or what-it-is text prints the bare option/id with no dash (`tests/test_lift.py`).
- Every id comparison — Short Title against block `id`, `--alternative` against `<alternative id>` — is made on the un-escaped, case-folded values through `id_key`: `ROOT ELEMENT FORM` and `OPEN and close PAIR` match, the un-escaped `ampersand & ANGLE <brackets>, …` matches the entity-bearing block while its `&amp;`-escaped spelling does not (`tests/test_locate.py`, `tests/test_lift.py`).

- The three subcommands are registered through the existing `add_subcommand` helper (each takes `MILESTONE_DIR` first), appear in `--help` (`tests/test_contract.py`), and are described in the module docstring with the id-comparison rule; the lookups `find_question`, `find_questions`, and `find_alternative` are module-level helpers for the later mutators; the tool adds no import (stdlib only), `grep '{{'` over `core/tools/open_questions.py` finds nothing, and no `claude`/`antigravity` word appears under `core/tools/`.

## Tool Add And Strip Subcommands

Add `add`, which takes the Short Title as an argument, reads the question text from `sys.stdin.buffer` as UTF-8 (refusing a terminal stdin and reading exactly one body per call), and appends a bare block with only its `<question>` child in canonical form, and `strip`, which takes one or more Short Titles and deletes every child between each block's `<question>` element and its `</open-question>` line while touching no dependent and no `<depends-on>` tag naming the block, rejecting an unknown id with the document unchanged and doing nothing on an already-bare block. `add` is the review pass's authoring write and `strip` is the user's hand-clear replacement for a stale recommendation, and both are verified by pytest cases including the stdin-refusal and duplicate-id or unknown-id errors.

**Verified:**

- `add MILESTONE_DIR SHORT_TITLE` reads the question text as the one body on standard input (`read_body` reads `sys.stdin.buffer` to end of file once and decodes it as UTF-8), appends a bare block — the `<open-question id="…">` wrapper and its one `<question>` child — after every existing block, and writes the whole document in canonical form with the id and text whitespace-folded to one line and the five entities escaped; success prints nothing and exits 0, and two `add` calls on the `empty` fixture reproduce `tests/fixtures/bare/open_questions.xml` byte-for-byte (`tests/test_add.py`).
- `add` refuses a terminal stdin without blocking — a pseudo-terminal on fd 0 in a subprocess and an `isatty()`-true stdin in-process each fail as `Error: the question text must be piped on standard input (as a quoted heredoc or a redirected file), not typed at a terminal`, exit 1, empty stdout, document unchanged, the terminal never read — and a closed stdin, an empty or whitespace-only body, and a non-UTF-8 body each fail as one `Error:` line with the document unchanged (`tests/test_add.py`).
- `add` rejects a duplicate id — a Short Title matching an existing block's id un-escaped, whitespace-folded, and case-folded — as `Error: an <open-question> block with the id "…" already exists`, exit 1, document byte-for-byte unchanged; an empty Short Title fails as `Error: the Short Title is empty`; a missing `open_questions.xml` fails with `does not exist` and `add` creates nothing; a malformed document fails as one `not well-formed XML` line and is left as it was (`tests/test_add.py`).
- `strip MILESTONE_DIR SHORT_TITLE...` takes one or more Short Titles (`nargs="+"`; none is argparse's exit 2) and, for each named block, deletes every `<alternative>`, `<applied-principle>`, `<depends-on>`, and `<recommendation>` child, leaving the wrapper and `<question>` intact as the canonical three-line bare block; success is silent with exit 0, several blocks are stripped in one call, a block named twice is stripped once, and ids match un-escaped and case-folded (`tests/test_strip.py`).
- `strip` touches no dependent and no `<depends-on>` tag naming the stripped block: after stripping `Escape hatch under sole writer` in the `annotated` fixture, `Root element form` still carries `<depends-on question="Escape hatch under sole writer" option="Strip subcommand"/>` and every other child, and every line of the document outside the stripped block is byte-identical to the fixture (`tests/test_strip.py`).
- `strip` of an unknown id, alone or among known ones, fails as `Error: no <open-question> block has the id "…"; the document holds …` (or `the document holds no blocks` on `empty`), exit 1, empty stdout, with the document byte-for-byte unchanged and no partial strip of the known ids; a missing document fails with `does not exist` and a malformed one as one `not well-formed XML` line, each left as it was (`tests/test_strip.py`).
- `strip` on an already-bare block does nothing: exit 0, silent, the document byte-for-byte unchanged and not even rewritten (same inode and mtime), and a bare block named beside an annotated one leaves only the annotated one stripped (`tests/test_strip.py`).
- The strip is one module-level per-block primitive, `strip_question(question)` (with `is_bare(question)` beside it), that returns whether it deleted anything and that `cmd_strip` applies per named block, saving only when something changed; `add` and `strip` are registered through the existing `add_subcommand` helper, appear in `--help` (`tests/test_contract.py`), and are described in the module docstring together with the stdin-channel rule.
- The tool stays stdlib-only (no new import), `grep '{{'` over `core/tools/open_questions.py` finds nothing, and no `claude`/`antigravity` word appears under `core/tools/`; the suite grew from 104 to 153 cases and passes under both `uv run pytest` (Python 3.13.5, pytest 9.1.1) and `uv run --no-project --python 3.9 --with pytest pytest` (Python 3.9.25, pytest 8.4.2), leaving no `__pycache__` under `core/`.
- `uv run scripts/build_hosts.py` rebuilt hosts/antigravity/ (37 files) and hosts/claude/ (38 files), `cmp` shows both `hosts/<host>/tools/open_questions.py` byte-identical to `core/tools/open_questions.py`, and `uv run scripts/build_hosts.py --check` passes.
